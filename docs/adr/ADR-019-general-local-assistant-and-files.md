# ADR-019: General local assistant and file artifacts

- **Status:** Accepted
- **Context:** The Ollama interface must support general questions, templates and campaign-playbook development rather than acting only as a campaign form. Users also need local reference uploads and downloadable results without introducing paid API calls or weakening campaign approval controls.
- **Decision:** Add persistent general conversations using the existing loopback-only Ollama manager and `llama3.2:3b`. General answers have no application tools. TXT, CSV and DOCX text can be supplied as untrusted prompt context; JPEG and PNG files are retained locally but explicitly marked unreadable by the configured text-only model. Requested TXT, CSV and DOCX results are stored as authenticated local artifacts. A deliberate **Prepare campaign** handoff supplies the conversation/playbook to the existing schema-constrained draft workflow.
- **Campaign boundary:** General chat cannot create or run a campaign. Handoff creates only a reviewable draft. Playbook overrides, paused creation, disabled weekly outreach and separate approval remain authoritative.
- **Storage and security:** Conversation records and attachment metadata are stored in SQLite. File bytes use random storage names under the application data directory; original names are display-only. Extensions, size, base64, text encoding and PNG/JPEG/DOCX signatures are validated. Downloads require the local session token and verify the resolved file remains inside the assistant storage directory.
- **Resource policy:** General chat shares the same single-generation lock and exact LightBurn/xTool detection as campaign drafting. Full local resources apply when neither protected application is running; protected mode applies only while one is detected.
- **Limitations:** The model has no web access, image understanding or image generation. DOC (legacy Word) is not accepted; use DOCX. Local 3B output may need editing, so generated files and campaigns remain reviewable artifacts rather than autonomous actions.
- **Alternatives considered:** A campaign-only chatbot; cloud chat/file APIs; enabling arbitrary filesystem tools; treating image filenames as if their visual content had been understood.
- **Rollback:** Disable the local AI setting or `ENS_CAMPAIGN_ASSISTANT_ENABLED`. Existing conversations and files remain local; manual campaign creation is unaffected.
