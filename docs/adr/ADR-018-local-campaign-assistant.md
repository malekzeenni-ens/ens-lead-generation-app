# ADR-018: Local campaign drafting with Ollama

- **Status:** Accepted
- **Context:** Campaign setup contains enough connected choices that a conversational planner can reduce operator effort. Cloud model calls would add recurring cost and send commercial planning context outside the local workstation. The workstation also runs LightBurn and xTool Creative Space, whose responsiveness takes priority while either is open.
- **Decision:** Run the campaign planner locally through Ollama using only `llama3.2:3b`. The model receives a versioned campaign playbook plus trusted local context and returns one schema-constrained proposal. It has no tools and cannot create, activate, run or delete a campaign. Drafts, revisions, assumptions, warnings and override decisions are persisted locally. A campaign is created only by the separate approval endpoint and is always created paused with weekly outreach disabled.
- **Playbook overrides:** Recommendations may be overridden, but a material departure must first be returned as `confirmation_required` with the normal recommendation, requested value and impact. The operator can confirm or reject it; only a recorded confirmation is supplied to the next generation. Provider limits, configured-provider checks, paused creation and disabled weekly automation are hard constraints and cannot be overridden.
- **Resource policy:** Normal model limits apply whenever LightBurn and xTool Creative Space are not running. Exact process-name detection switches to a smaller context/output limit and unloads the model after the request only while either protected application is running. Normal mode resumes automatically after they close. The protection can be disabled in workspace settings.
- **Network boundary:** The Ollama URL is validated as loopback HTTP. Campaign drafting does not call a paid AI API. A generated campaign can still select an independently configured billable discovery provider such as Google Places; that selection is warned about and has no effect until the paused campaign is later run by the operator.
- **Alternatives considered:** Cloud LLM APIs; a deterministic campaign builder with AI wording layered on top; an unconstrained local agent with campaign tools; always restricting the model to the smallest resource profile.
- **Consequences:** Ollama and the model must be installed separately. A 3B model may occasionally require clarification or manual correction, so schema and domain validation remain authoritative and the manual campaign workflow remains available.
- **Security/compliance impact:** Prompts and outputs stay on loopback, user content is treated as untrusted planning input, every accepted override is auditable, and no model output crosses the existing human approval or campaign-run boundaries.
- **Rollback/migration:** Disable the local campaign assistant in Settings or set `ENS_CAMPAIGN_ASSISTANT_ENABLED=false`. Existing drafts remain local records and manual campaign creation continues to work.
